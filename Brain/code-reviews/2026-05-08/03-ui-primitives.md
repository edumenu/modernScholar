# UI Primitives Review

## Summary

The primitives layer is broadly in good shape: Base UI is consistently used as the underlying a11y engine, `cn()` is used everywhere, `data-slot` compound patterns are followed, OKLCH tokens are referenced through CSS variables, and React 19 ref-as-prop is in use across most files. The main risks cluster around (1) duplicate / divergent code paths (`table.tsx` and `table/table.tsx`; `pagination/pagination.tsx` references Button props that don't exist; `slider` imports Radix instead of Base UI), (2) glassmorphism rule violations (full‑page mobile menu backdrop, `mobile-menu` button skipping the shared `glassPill` token, `Sheet` overlay falling back to `glass-elevated`), (3) a noticeable `'use client'` and SSR safety footprint on a few primitives that don't need it (`Card`, `Skeleton`, `Textarea` are clean — but `Carousel`, `MobileNav`'s `Curve`, and `theme-toggle`'s `useSyncExternalStore` mounted-pattern have issues), and (4) some accessibility regressions (`Checkbox` label has no associated text input control connection beyond visual wrapping; `Slider` thumbs have only `aria-label` from `thumbLabels`; `useFocusTrap` returns focus from drawer, but the close happens on `pathname` change without resetting `selectedIndicator`).

## Critical issues (a11y / correctness)

- `src/components/ui/pagination/pagination.tsx:52-61` — `PaginationLink` passes `nativeButton={false}` and `render={...}` to `Button`, but `Button` (`button/button.tsx:61-67`) does not accept either prop. `nativeButton` is a Base UI Button.Props field that is preserved via spread, but `render` is silently dropped because `Button` does not forward it to `ButtonPrimitive` — meaning `PaginationLink` is currently rendering a `<button>` (with the variant classes and ripple) rather than the intended `<a>` inside a `<button>`. This breaks `aria-current="page"` semantics and right-click / cmd-click navigation. Fix: either add explicit `render` passthrough on `Button`, or replace `PaginationLink` with `ButtonLink` / a plain `<a>` that uses `buttonVariants(...)` directly.
- `src/components/ui/slider/slider.tsx:3` — imports from `@radix-ui/react-slider` while the rest of the system uses `@base-ui/react` (Base UI does ship a `slider/` module). This adds a second a11y/state engine to the bundle and breaks the consistency of `data-slot` / Base UI styling hooks. Fix: migrate to `@base-ui/react/slider` and drop the `@radix-ui/react-slider` dependency, or document the deliberate exception.
- `src/components/ui/slider/slider.tsx:28-31` — slider thumbs only get `aria-label` when the consumer passes `thumbLabels`. Without it they have no accessible name. Fix: fall back to `aria-label={`Value ${index + 1}`}` and require/document `thumbLabels` for multi-thumb sliders.
- `src/components/ui/checkbox/checkbox.tsx:24-30` — wrapping `<label>` has `cursor-default` and `select-none` and the label's text node is a `<span>`, but the `CheckboxPrimitive.Root` is not given an `id` nor an `aria-label`. Screen readers will pick up the label association via wrapping, but the visually-distinct interactive root has no name when `children` is omitted (icon-only checkboxes). Fix: forward an optional `aria-label` / `id`+`htmlFor` pair, or require `children`.
- `src/components/ui/four-oh-four/not-found-client.tsx:67-69` — `Curve` component reads `window.innerHeight` at module / render time inside an SVG path string. Because this file is `'use client'` and the component renders only inside a portal that is mounted client-side, this works at runtime — but the function references `typeof window !== "undefined"` *while computing the initial path string*, then again for the target path, so the *initial* path is `M100 0 L100 900 …` on the very first paint after hydration if the component were ever to evaluate before window is defined (Next can prerender client components). More importantly, the curve is computed once and never recomputed on viewport resize — on a phone rotated mid-session the path is wrong. Fix: useEffect + state for `innerHeight`, or `useSyncExternalStore` with a resize listener.
- `src/components/ui/header/mobile-menu.tsx:67-96` — same `Curve` lives here (same issue): hardcoded once and wrong on resize.
- `src/components/ui/header/mobile-menu.tsx:288-296` — full-screen backdrop uses `backdrop-blur-md` directly. Per the design system, glassmorphism is allowed on Z-2+ floating elements (modals, dropdowns, etc.), and a mobile drawer overlay qualifies — so the *blur* is fine, but it bypasses the shared `glass-*` utilities that include `prefers-reduced-transparency` and `prefers-contrast:more` fallbacks (see `globals.css:449-512`). Users who opt out of transparency will still get the heavy blur. Fix: use `glass-heavy` (or `glass-elevated`) on the backdrop and rely on `globals.css` fallbacks.
- `src/components/ui/header/mobile-menu.tsx:257-263` — the mobile menu button hand-rolls `border-white/40 bg-white/25 ... backdrop-blur-2xl ...` instead of the shared `glassPill` token from `styles.ts`. Same fallback gap as above and a token drift risk. Fix: compose `cn(glassPill, "size-11.5 ...")`.
- `src/components/ui/sheet/sheet.tsx:31-33` — `SheetOverlay` defaults to `glass-elevated` only when `className || "glass-elevated"` evaluates truthy on the *prop side*. Because `className ||` short-circuits, any consumer passing a non-empty class (even `"opacity-0"`) loses the glass entirely. This pattern also makes the default impossible to extend without re-applying `glass-elevated`. Fix: `cn("...transition...", className ?? "glass-elevated")` and accept additive merging.
- `src/components/ui` — duplicate Table component: `table.tsx` (root) and `table/table.tsx`. They diverge: the folder version uses the design tokens (`bg-surface-container-high`, `even:bg-surface-container-low`, `text-on-surface-variant`), the root file uses generic `bg-muted/50`, `text-foreground` and includes `border-b` on rows. Importers will pick whichever path resolves first and get inconsistent results. Fix: delete `src/components/ui/table.tsx` and re-point any import to `./table/table`.

## High-impact improvements

- `src/components/ui/header/header.tsx:65-93` — `<header>` has `position: fixed` while it is also wrapped in `ScrollAnimatedHeader` which is `position: fixed`. Two stacked fixed elements can produce a 2× translate on iOS Safari at certain rubber-band events; also any consumer relying on `useScroll({ target })` against the document layout will see the inner `<header className="fixed">` contributing 0 height. Fix: drop `fixed inset-x-0 top-0 z-50` on the inner `<header>` and let the wrapper carry positioning, or convert the wrapper to a non-fixed container.
- `src/components/ui/header/header.tsx:85-93` — `ResizeObserver` only observes the *first nav item's parent*. If `linkRefs.current[navItems[0]?.href]` hasn't mounted yet (e.g., first paint with reduced motion off), `parentElement` is null and the observer never starts. Fix: observe `headerRef.current` (or a stable ref) instead of the first link's parent.
- `src/components/ui/footer/footer.tsx:131-150` — the "reveal" footer pattern uses `clipPath: "polygon(0% 0, 100% 0%, 100% 100%, 0 100%)"` (which is just a rectangle and so does nothing) plus a fixed inner `h-[50vh]` panel. The fixed panel paints over Lenis content and creates a stacking context that traps interactions. Combined with the `useReveal` toggle, on tall content this is fine, but on shorter routes (`/contact`, blog index when empty) the footer covers half the viewport from the start. Fix: remove the no-op clip-path; gate the fixed panel on `useReveal && documentScrollHeight > 1.5 × viewport`.
- `src/components/ui/header/theme-toggle.tsx:14-18` — `useSyncExternalStore(() => () => {}, () => true, () => false)` is a clever mounted check, but it forces a re-render on every commit because the subscribe callback returns a no-op (no real subscription). This works, but `useHasMounted` (already in `src/hooks/use-has-mounted.ts`) is the canonical hook used elsewhere — use it for consistency and so a Suspense-friendly version can be applied uniformly.
- `src/components/ui/dropdown-menu/dropdown-menu.tsx:44-47` — the `glass-panel` className string is ~700 chars; the inline `**:data-[slot$=…]` selectors duplicate between `DropdownMenuContent` and `DropdownMenuSubContent` (lines 44-46 vs 142-143). Extract a shared base string constant to keep them in sync — currently `SubContent` already drifts (`bg-surface-container-lowest` for items vs `bg-surface-container-highest` in the parent).
- `src/components/ui/checkbox/checkbox.tsx:1-77` — does not implement the `compound` `data-slot` pattern (no `data-slot="checkbox"`), so styling/selectors used elsewhere (`*:data-[slot=…]`) won't match. Also no `id` / `htmlFor` — the wrapping label works for click-to-toggle, but consumers using `Label` from `label/label.tsx` (which expects `peer-disabled` semantics) will not get a peer relationship. Fix: add `data-slot="checkbox"`, accept `id` and forward to `CheckboxPrimitive.Root`.
- `src/components/ui/textarea/textarea.tsx:10` — references `border-input bg-input/30` and `focus-visible:border-ring focus-visible:ring-ring/50` (generic shadcn tokens) while `Input` uses `border-outline-variant/20 bg-surface-container` and `focus-visible:border-secondary focus-visible:ring-secondary/30` (Academic Curator tokens). The two form controls are visually inconsistent. Fix: align `Textarea` with `Input`'s token usage.
- `src/components/ui/badge/badge.tsx` — uses `useRender` from Base UI (good), but `[a]:hover:bg-...` selectors target descendant `<a>` elements; if the badge IS rendered as `<a>` via `render={<a/>}`, the selector won't match (it would be `:is(a):hover` or `[&[role=link]]:hover`). Fix: add `[&[href]]:hover:bg-…` or equivalent.
- `src/components/ui/carousel.tsx:78-89` — keyboard handler is on `onKeyDownCapture`, which intercepts every key event in the subtree before any input can use them. Inputs / textareas inside a `CarouselItem` will lose left/right arrow text-cursor movement. Fix: switch to `onKeyDown` and bail when the event target is editable (`event.target.closest('input, textarea, [contenteditable=true]')`).
- `src/components/ui/tabs/tabs.tsx:62-64` — overlapping background utilities: line 62 sets `data-active:bg-surface-container-high` for `variant=line`, line 63 unconditionally sets `data-active:bg-surface-container-lowest`. With `cn`/`tailwind-merge`, the *last* class wins, but `cn`'s merge happens before the variant string is parsed because both are part of the same `cn(...)` call — order is preserved. Result: line variant active state may flicker between two backgrounds depending on which class is last. Fix: gate line 63's classes on `group-data-[variant=default]/tabs-list:` (or similar) so they don't apply to `line`.
- `src/components/ui/page-transition.tsx:9-18` — applies a `motion.div` keyed on pathname around the entire app body. Every navigation re-renders the full page tree from scratch and triggers a layout-affecting `y` transition. This causes a forced reflow on every route change and breaks Lenis's scroll restoration. The 0.15s duration and `y: 8` are minor, but the wrapper introduces a new offsetParent which can shift `position: sticky` children. Fix: animate `opacity` only, or scope this transition to `<main>` with `prefers-reduced-motion` short-circuit.

## Medium-impact improvements

- `src/components/ui/button/button-link.tsx:55-71` — unlike `button.tsx`, `ButtonLink` swallows the consumer's `onMouseEnter/Leave/Down/Move` handlers when ripple is active (it doesn't call `props.onMouseEnter?.(e)` first; spreads happen *after* the override). Consumers can never observe these events. Fix: mirror `button.tsx`'s call-then-delegate pattern.
- `src/components/ui/card/card.tsx:5-21` — `Card` defines a `size` variant via `data-size` but doesn't use CVA. With only two values that's fine, but adding new tonal variants (e.g. `tinted`, `outlined`) will require touching every CardHeader/Content/Footer. Consider migrating to CVA for parity with `Button`/`Badge`.
- `src/components/ui/dialog/dialog.tsx:34-39` — `DialogOverlay` uses `bg-black/80 supports-backdrop-filter:backdrop-blur-xs` instead of `glass-heavy` / `glass-elevated`. This bypasses the design system's reduced-transparency fallbacks. Backdrops *are* allowed glass per SystemDesign. Fix: replace with `bg-black/40 glass-heavy` (or accept the simpler tonal black if that's the intended look — but document it).
- `src/components/ui/header/mobile-menu.tsx:233-236` — directly mutates `prevPathname` via `setState` during render to close the menu on navigation. This pattern works but is brittle; the React canonical idiom for "derive from prop" is `useSyncExternalStore` of the pathname or `useEffect(() => setIsOpen(false), [pathname])`.
- `src/components/ui/header/mobile-menu.tsx:139` — `useState(pathname)` initializes `selectedIndicator` once, so navigating with the menu open leaves the dot pointing at the previous active route. Fix: derive `selectedIndicator` from `pathname` via `useEffect` or treat it as ephemeral hover state only.
- `src/components/ui/four-oh-four/not-found-client.tsx:153-165` — `mounted` toggled via `startTransition` is unnecessary here; the only effect is delaying Spline mount by one frame. This delay defers the Spline import past LCP but `lazy()` already does that. Drop the transition.
- `src/components/ui/four-oh-four/not-found-client.tsx:32-41` — `floatingIcons` array has 8 motion.divs each running infinite mirror animations; even with reduced-motion guard this is heavy on lower-end devices. Consider `transform-gpu` and reducing duration variability, or pause via IntersectionObserver when off-screen.
- `src/components/ui/avatar/avatar.tsx:62-67` — `AvatarBadge` uses `bg-blend-color` which has no effect without a backdrop or background-image; appears to be a leftover. Remove.
- `src/components/ui/sonner/sonner.tsx:34-36` — `--normal-border` is hardcoded `rgba(219, 193, 188, 0.15)`; should reference `var(--outline-variant)` or similar. Same for the toast classNames using `glass-heavy` (good!), but the inline rgba breaks dark-mode theming.
- `src/components/ui/separator/separator.tsx:12-19` — defaults to `data-horizontal:` / `data-vertical:` selectors while the component spreads orientation. Base UI sets `data-orientation` not free `data-horizontal` — verify Tailwind v4 attribute selector mapping. Actually safe (Tailwind v4 maps `data-horizontal:` to `[data-orientation=horizontal]`), but worth a comment.
- `src/components/ui/styles.ts:1-3` — `glassPill` includes `dark:shadow-neu-primary` which is the *button* neumorphic shadow, not a glass shadow. Suggests copy-paste; should be `dark:shadow-[0_8px_32px_rgba(0,0,0,0.25)]` or a dedicated `--shadow-glass` token.
- `src/components/ui/header/header.tsx:115` and `:191` — `lg:flex hidden` ordering matters but `tailwind-merge` will keep both; effective CSS is `display:none` until lg. Order is fine. However `hover:shadow-[0_8px_40px_rgba(31,38,135,0.22)]` uses a *blue* tinted shadow (rgb 31,38,135) on what should be a warm-brown branded element — see SystemDesign Section "Ambient tinted shadows (warm brown base, 4-6% opacity)". Replace with `rgba(118, 49, 45, 0.06)` (primary-ish).
- `src/components/ui/custom-cursor.tsx:124` — same blue-tinted ambient shadow on the cursor; `0 2px 8px rgba(0,0,0,0.15)` is fine, but the `0 0 0 1px rgba(255,255,255,0.15)` ring is invisible against the warm cream surface. Use `var(--surface)` ring.
- `src/components/ui/custom-cursor.tsx:115-128` — sets `display: 'none'` via inline style when `!isActive`, but the motion event listeners (the surrounding component still subscribes mouse events when *enabled*). When disabled, the early-return `useEffect` correctly bails — good. Minor: `z-9999` is a magic number; use `z-50` or define `--z-cursor`.
- `src/components/ui/parallax-layer.tsx:21-25` — fine, but lacks `prefers-reduced-motion` guard; `useParallax` should handle it but worth verifying.
- `src/components/ui/animatedSection/animated-section.tsx:91-97` — under reduced-motion, returns a plain `<div>` with no initial styles, so the children appear instantly. Good. But the type for `customInitial` and `customAnimate` is `TargetAndTransition` which includes `transitionEnd`/`transition` — Motion will warn when these are passed alongside `transition`. Restrict to `Target` or document.
- `src/components/ui/animatedLines/animated-lines.tsx:97-135` — chars mode renders one `motion.span` per character; for a 60-char heading that's 60 layers + 60 transitions. On low-end devices this is observable. Consider `LazyMotion` + `m.span` to reduce per-instance JS.
- `src/components/ui/dialog/dialog.tsx:96-99` — `DialogFooter`'s `showCloseButton` defaults to `false` while `DialogContent`'s defaults to `true`. Inconsistency; pick one default and document.
- `src/components/ui/navigation-menu/navigation-menu.tsx:91` — string is enormous; consider extracting to a constant. Also `data-ending-style:data-activation-direction=left:` Tailwind variant chaining is non-standard JIT syntax — verify it actually compiles in Tailwind v4 (should be `data-ending-style:[&[data-activation-direction=left]]:translate-x-[50%]`).
- `src/components/ui/page-shell/page-shell.tsx:11-21` — duplicates the `id="main-content"` that `<a href="#main-content">` in `header.tsx` jumps to. Good. But `<main>` is being rendered by `PageShell` *and* by routes that don't use `PageShell` (e.g., `four-oh-four/not-found-client.tsx:173` also has a `<main>`), causing two `<main>` elements on the 404 route. Fix: not-found should not render `<main>` if it's nested inside the layout's main.

## Low / nits

- `src/components/ui/dialog/dialog.tsx:73-74` — orphaned closing tag with extra blank line: `<Icon ... />` formatted oddly.

- `src/components/ui/separator/separator.tsx:13` — Base UI `Separator` is exported as named primitive; `<SeparatorPrimitive>` is being used as the root component (correct for the namespace import pattern).
- `src/components/ui/tooltip/tooltip.tsx:8` — `delay = 0` is aggressive (instant tooltips fire on every micro-hover). 200-400ms is the WCAG-friendly default.
- `src/components/ui/button/button.tsx:11-12` — first className string is ~700 chars on one line; readability suffers. Consider extracting `baseButtonClass`.
- `src/components/ui/header/theme-toggle.tsx:13` — `useSound` runs only client-side but is loaded eagerly. Consider dynamic-importing `use-sound` to shave the audio decoder from the initial header bundle.
- `src/components/ui/animatedLines/animated-lines.tsx:107` — `inline-block overflow-hidden pt-[0.1em] pb-[0.2em]` per character will make `text-shadow` and `filter: blur` clip oddly when `variant=blurIn`. Document the limitation.
- `src/components/ui/footer/footer.tsx:51,72` — section `<h3>` uses `font-sans` explicitly. Fine — sans is the default; class is redundant but harmless.

## Notable strengths

- Universal `cn()` use, consistent `data-slot="…"` attributes, and Base UI as the a11y foundation across nearly every primitive.
- Clean React 19 ref-as-prop adoption (`Input`, `Button`, `Slider`) — no `forwardRef` legacy noise.
- `Header` skip-link (`src/components/ui/header/header.tsx:97-102`) is correct, focusable-only-on-focus, and points at `#main-content`.
- `MobileMenuButton` (`src/components/ui/header/mobile-menu.tsx:227-302`) handles `aria-expanded`, `aria-controls`, focus return after close, and uses `useFocusTrap` inside the drawer — this is a high-quality pattern.
- `AnimatedSection` and `AnimatedLines` correctly short-circuit under `useReducedMotion()` and only animate `opacity`/`transform`/`filter`.
- `Card` uses tonal layering (`bg-surface-container-low`) with no glass — exactly matches the SystemDesign rule for Z-1.
- `Button` ripple system (`useRipple`) cleanly delegates events instead of overwriting consumer handlers, sets `data-cursor` for the custom-cursor system, and gates ripple on variant.
- `Sheet`, `Dialog`, `Popover`, `Tooltip`, `DropdownMenu` content nodes correctly use `glass-panel` / `glass-heavy` per the elevation system — Z-2+ floating elements only.
- `four-oh-four` provides a static SVG `ZeroRing` fallback for reduced-motion users instead of just disabling animations — thoughtful.
- `Pagination` parent `<nav role="navigation" aria-label="pagination">` is proper landmark structure.
