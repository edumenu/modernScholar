# Blog + Contact Features Review

## Summary

The blog stack is in good structural shape: an MDX pipeline driven by a single Zod-validated loader (`src/lib/blog.ts`), pages that hand server-rendered MDX bodies down through `BlogDetail` as `children`, and a sensibly tiered `getRelatedPosts` ranker (series → tag overlap → category → recency). MDX overrides include a sound h3-anchor strategy that mirrors `extractHeadings` so reading-progress dots resolve. However, several issues deserve attention: the blog-grid skeleton diverges from the real grid in noticeable ways (causes a guaranteed CLS on first paint), `MobileContactImage` and `ContactFormSection` have unnecessary `mounted` gating for `next-themes` that masks priority `<Image>` and Spline rendering, the `<PullQuote>` is a `figure` containing a `<blockquote>` rather than the semantically clean `<blockquote><footer>` pattern, the focus-trap hook never restores focus on deactivation (regression risk for accessibility), and `useScrollLock` uses a module-level lock counter that is unsafe across Strict Mode double-invokes. There's also a stale "T08/T11/T14" migration thicket of structural-shape interfaces that should be replaced now that `@/data/blog-posts` no longer exists. The blog detail content card and inline scholarship card correctly avoid glassmorphism (cards-not-glass rule respected).

## Critical issues

- `src/hooks/use-focus-trap.ts:26-60` — Hook never restores focus to the previously focused element when `active` flips false or the component unmounts. Standard a11y expectation for a focus trap (modals, sheets, mobile menu) is to return focus to the trigger. Capture `document.activeElement` as `previouslyFocused` on mount/activation and call `previouslyFocused?.focus({ preventScroll: true })` in the cleanup. The mobile menu and sheet consumers (`mobile-menu.tsx`, `comparison-sheet.tsx`, `scholarship-filters-mobile.tsx`, `expanded-scholarship.tsx`) all rely on this hook and currently leak focus to `<body>` after close, which screen-reader users perceive as the focus going "nowhere."
- `src/hooks/use-scroll-lock.ts:6-21` — Module-level `let lockCount` is shared across all consumers but mutated inside `useEffect`. In React 19 dev (Strict Mode double-invokes effects) the increment runs twice and the cleanup runs twice, so the count balances per-consumer — but if Lenis fails to mount on first render (`useLenis()` returns `undefined`) the early `return` skips the `lockCount++` while a later remount will double-decrement. Track lock state with a ref or a small Zustand store, or guard `lockCount--` with the same `lenis` truthiness check. Also: `lenis.stop()` is only called when the lock is *first* acquired? No — every consumer calls `lenis.stop()` on mount, but only the last cleanup calls `lenis.start()`. That's correct, but make the asymmetry explicit and add a comment.
- `src/components/blog/blog-grid-skeleton.tsx:77-80` — Skeleton renders 8 cards while real grid renders up to 8 (`PAGE_SIZE=9` minus 1 featured). Fine when a featured post exists, but the real grid renders 9 cards when there is *no* featured post on page 1 (or any non-page-1). The skeleton always shows 8 → 1-card layout shift on subsequent paginations and on slug pages with no featured. Match the real grid's worst case (9) or detect the route. Same concern: skeleton's `FeaturedCardSkeleton` is unconditional at line 74, yet the real grid hides the featured card on pages 2+ — so on `/blog?page=2` users see a 21:9 hero placeholder for ~100ms that then disappears. The skeleton is render-time-only on the initial server render of `/blog`, which currently has no `loading.tsx` so this is dormant — but if a `loading.tsx` is added at `src/app/blog/loading.tsx` (recommended), this divergence will manifest.
- `src/components/contact/contact-form-section.tsx:153-184` — `MobileContactImage` gates the `<Image>` behind `mounted` (set in `useEffect`). The result: every mobile contact-page visit shows an `animate-pulse` placeholder for one frame before the priority image renders, **and** Next.js can't begin loading the image until after hydration. This defeats `priority`. The image switches by theme, but `next-themes` provides `defaultTheme="system"` resolution at render time — render the dark image as a `<picture>` with `media="(prefers-color-scheme: dark)"` source so the browser picks the correct one before JS executes. Same problem at `contact-form-section.tsx:188-227` for the Spline scene: Spline already needs JS, so `mounted` gating is mostly fine there, but the empty `splineFallback` when `!mounted` plus the in-component fallback inside `<SplineScene>` (`spline-scene.tsx:39-43`) is double fallback.
- `src/components/blog/blog-detail-hero-image.tsx:25-34` — Two stacked overlays on the hero (`mix-blend-multiply bg-primary/30` + `bg-linear-to-b from-transparent to-primary-900/35`) on the article hero with no theme awareness. In dark mode this stacks even more darkness on already-low-contrast images and reduces text legibility on the title that sits *under* the image (or rather, above — title is rendered first, so this only affects the image itself). It's not strictly a regression, but the multiply pass at 30% opacity is heavy enough that it qualifies as art direction the user can't opt out of with `prefers-reduced-transparency`. Tone the second overlay down to `to-primary-900/15` in dark mode or guard with `dark:`.

## High-impact improvements

- `src/components/blog/blog-grid.tsx:51-145` — Component is doing too much. Extract: (1) the `useQueryState` triple + handlers into a `useBlogFilters()` hook (mirrors `useScholarshipFilters`); (2) `getPageNumbers` lives at the bottom — fine, but the pagination JSX block (211-267) is 56 lines and could be its own `<BlogPagination>` component reused by the scholarships listing if/when it gets pagination. Both reduce the client bundle that ships for `/blog` (this file is `"use client"` and currently pulls in `motion/react` AnimatePresence, lenis, nuqs, and the entire pagination ink-spread component family).
- `src/components/blog/blog-grid.tsx:101-105` — The "normalize URL if requested page is out of range" effect runs `setPage` inside `useEffect`, which causes a second render. Move to derived state via `useMemo` and only `setPage` on the *user* action paths (`goToPage`, `handleCategoryChange`, etc.). The current code re-renders + replaces history every time someone navigates to `/blog?page=999`.
- `src/components/contact/contact-form-section.tsx:1-371` — File is 371 lines and contains four sub-components (`NudgeArrow`, `CopyEmailButton`, `QuestionRouting`, `MobileContactImage`) plus the main one. Split out `nudge-arrow.tsx`, `copy-email-button.tsx`, `question-routing.tsx`, `mobile-contact-image.tsx`. None of them depend on the parent's state and the file is a hot path (contact page entry).
- `src/components/blog/reading-progress.tsx:45-66` — `useMotionValueEvent("change", ...)` runs on every scroll frame and inside the callback you call `Math.round`, `setPercentage` (state), `setIsComplete` (state), then a synchronous `for` loop calling `getElementById` + `getBoundingClientRect` for *every* heading. With 6 headings that's 6 layout reads per scroll frame. Wrap the section detection in `requestAnimationFrame` and cache element refs in a `useMemo`/`useRef` instead of re-querying by id every frame. Also: `setPercentage` on every frame triggers a React re-render; consider using a `motion` `<motion.span>{count}</motion.span>` with `useTransform(scrollYProgress, [0,1], [0,100])` and rendering via `useMotionValue` text rather than React state.
- `src/components/blog/reading-progress.tsx:32-36` — `useScroll({ target: articleRef })` works only after `articleRef` is attached. Because `BlogDetail` renders `articleRef` on the `<article>` containing the `children`, but `ReadingProgress` is rendered *inside* the sidebar `<aside>` (sibling of article), the ref is fine — but the `offset: ["start start", "end end"]` causes the progress to reach 100% when the article's bottom hits the *bottom* of the viewport, not when the user has actually finished reading. For long articles this means "100%" fires while the conclusion paragraph is still off-screen below. Use `["start start", "end start"]` so 100% = article bottom at viewport top.
- `src/components/blog/blog-detail-content.tsx:51-53` — The MDX body is wrapped in a `<div className="space-y-8">`. With the MDX overrides setting `mt-4` on `<p>` and `mt-12` on `<h2>` etc., the `space-y-8` adds **on top of** the explicit margins → unpredictable rhythm. Either drop `space-y-8` (let MDX overrides own spacing) or drop the `mt-*` from `mdx-components.tsx`. Currently both fight.
- `src/components/blog/blog-detail-content.tsx:23-25` — Title uses `text-3xl ... lg:text-5xl` but no `max-w-prose` or measure constraint. With Noto Serif at 5xl, lines run to ~120ch on a 1280px viewport. Cap at `max-w-[20ch]` or wrap in a `max-w-4xl` container — typography tokens should respect a measure of 50-75ch for body and 20-40ch for display.
- `src/components/blog/blog-detail.tsx:85` — `grid-cols-[260px_1fr]` puts the *content column* in `1fr` with no upper bound. Long-form prose without `max-w-prose` runs full width on `xl+` screens (1440px-260px-gap = ~1100px line length). Add `max-w-prose` (or `max-w-[68ch]`) on the content `<div>` at line 88.
- `src/components/blog/related-posts.tsx:43-71` — Works but `RelatedPostItem` requires `id: string | number`, and `[slug]/page.tsx:82` does `id: p.slug`. The mapping is duplicated work — `RelatedPosts` should accept the new `BlogPost[]` directly. The "T08/T11/T14 cascade" comment is stale: there is no `@/data/blog-posts` anymore (verified via `ls src/data/`). Same applies to `BlogCard.BlogCardPost` (`blog-card.tsx:11-33`), `BlogCardFeatured.BlogCardFeaturedPost`, `BlogGrid.BlogGridPost`, `BlogDetail.BlogDetailPost`, `BlogDetailContent.BlogDetailContentProps`. Replace the structural-shape duplications with `Pick<BlogPost, ...>` or import the `BlogPost` type directly.
- `src/components/blog/blog-card.tsx:130-136` and `:97-105` — `onError` on the inner `<Image>` mutates `target.style.display = "none"` to hide the broken avatar — but the parent `<div>` keeps its `bg-surface-container-high` placeholder, so it looks like a deliberate placeholder. Fine, but the same image errors don't propagate to the author *text*, so a broken avatar plus author name reads as "user with no profile pic." Either fall back to author initials or hide the whole avatar slot.
- `src/components/contact/contact-form-section.tsx:196-202` — `useMemo` on `splineUrl` is fine, but `<SplineScene key={resolvedTheme} ...>` (line 220) tears down and re-mounts the entire Spline runtime on theme switch. Spline's `setVariable` API can swap colors without remount. Out of scope for this review, but a known performance sink — note for the Spline pass.

## Medium-impact improvements

- `src/components/blog/blog-card.tsx:36-50` — CVA has only one variant axis (`variant: default | compact`) where `compact` and `default` differ in `hover:shadow-xl` vs `hover:shadow-lg` plus body conditional rendering at runtime. CVA isn't buying much; consider just two components or a single `compact` boolean prop.
- `src/components/blog/blog-card.tsx:196-219` — `ReadingTimeBars` parses `readTime` (`"5 min read"`) with `parseInt`. The data comes from `@/lib/blog.ts:217` (`${minutes} min read`) which is reliable, but the `parseInt(readTime)` will silently default to 5 when the string format ever changes. Either pass `minutes: number` directly (it's already computed) or stringify only at the leaf.
- `src/components/blog/blog-card.tsx:147-162` — `<Button>` rendered inside a `<Link>`. The Button likely renders a `<button>` element, producing nested-interactive markup (`<a><button>...</button></a>`) which is invalid HTML and breaks expected keyboard semantics (Tab lands on the link or the button depending on browser). The `e.stopPropagation()` patches the click but does not fix the markup. Use `Button asChild` semantics or render the button as a `<span>` styled like a button. Same issue at `blog-card-featured.tsx:117-128`.
- `src/components/blog/pull-quote.tsx:13-37` — Element is `<figure>` containing `<blockquote>`. Fine semantically, but the quotation marks at lines 14-16 and 31-34 use literal `&ldquo;` / `&rdquo;` text inside a 120px `<div>` rather than CSS `::before`/`::after`. Screen readers will announce them as "left double quotation mark" before reading the actual quote. Use `aria-hidden="true"` on those decorative divs (they already have `pointer-events-none` and `select-none`, but no aria-hidden).
- `src/components/blog/callout.tsx:60-81` — `<aside role="note">` is good. The icon has `aria-hidden="true"` ✓. But the visible label "TIP / WARNING / NOTE" is rendered as `<p>` text *inside* the callout body, while the same label is also in `aria-label={label}`. AT users hear the label twice. Either drop `aria-label` (let the visible label suffice) or visually-hide the inner `<p>` from AT.
- `src/components/blog/inline-scholarship-card.tsx:53-62` — Rendered as `<aside>` inside MDX prose flow. Semantically `<aside>` should be tangentially related content — that's correct. But it's also given `data-slot="inline-scholarship-card"` and uses `not-prose` (Tailwind Typography). The project doesn't appear to use `@tailwindcss/typography` here (the MDX components do their own styling), so `not-prose` is a no-op. Remove or document.
- `src/components/blog/blog-detail-hero-image.tsx:11-37` — Component is `"use client"` only because of `useState` for `imgError`. The error fallback could be handled server-side with no client JS by using a known-good `src` and removing the runtime fallback. If client-side fallback is required, at least gate the dual-overlay on the success case so a broken-image fallback still shows the silhouette.
- `src/components/blog/mdx-components.tsx:127-166` — The `img` override falls back to a plain `<img>` when MDX omits `width`/`height`. Since most authored MDX won't include width/height, this fallback is the *common* case, defeating Next.js Image optimization. Consider passing reasonable defaults (e.g., `width={1200} height={675}` for 16:9 hero images) or extracting dimensions from the file at build time via `remark-mdx-images` or `next/image` with `fill` + a wrapped aspect-ratio container.
- `src/components/blog/mdx-components.tsx:37-45` — `h2` override has no `id` / `scroll-mt-32` even though `h3` does. If posts ever introduce `## ` headings, the table-of-contents (which only tracks h3) will skip them silently. Either also slugify h2 (and update `extractHeadings` to match) or document that posts must use h3 only — `ScholarshipBlogs.md` convention does say "In-post sections use `### ` (h3); the post title uses `## **Bold**`", but the title is rendered *outside* MDX (at `blog-detail-content.tsx:23`) so any `## ` in MDX would be a body-level h2 with no anchor.
- `src/components/blog/blog-grid.tsx:108-112` — `setTimeout(() => lenis.resize(), 100)` is a hack to recompute after layout. React 19's `useLayoutEffect` (or the Motion `useAnimationFrame` API) is more reliable. The 100ms is a magic number that breaks when the grid renders 1 vs 9 cards (different layout times).
- `src/components/contact/contact-form-section.tsx:259-266` — `<CTAButton ... onClick={() => { window.location.href = mailto: ... }}>`. Should be `<Link href="mailto:..." />` styled as the button — current implementation breaks middle-click (open in new tab/window doesn't apply to mailto, but a link is still more semantic and preserves keyboard `Enter` behavior, screen reader semantics, and right-click "Copy link address"). Same concern with the screen-reader announcement: the button announces as "SEND EMAIL button" rather than "SEND EMAIL link to dearmodernscholar@gmail.com."
- `src/components/contact/contact-form-section.tsx:269-338` — The nudge arrow has 6 nested `motion.div` props with three different shapes (init/animate/exit). Each conditional spawns a new object on every render — not a perf issue at this scale but readability is rough. Define `NUDGE_VARIANTS` and `NUDGE_VARIANTS_REDUCED` once at module scope and pass via `variants={...}` + `initial="hidden"` / `animate="visible"` / `exit="exit"`.
- `src/components/contact/contact-faq.tsx:42-94` — Accordion is correctly built (aria-expanded, aria-controls, region role). But: only one item open at a time (`useState<number | null>`), no keyboard arrow-key navigation between headers (WAI-ARIA accordion pattern recommends Up/Down to move between buttons). For 3 items it's tolerable, but worth a note.
- `src/components/blog/blog-filters.tsx:43-49` — `useEffect` calls `lenis.stop()`/`lenis.start()` directly, duplicating `useScrollLock`. Use the hook for consistency (and to participate in the ref-counted lock).
- `src/components/blog/related-posts.tsx:108-117` — `CarouselItem className="basis-full ... md:basis-1/2 lg:basis-1/3"` with carousel `align: "start"`. Fine, but on lg with 3 visible and only 3 total related posts, prev/next arrows are still rendered at line 95-104 and only `count > 1` gates the count display — when there's only 1 page of slides, the arrows don't navigate anywhere. Hide arrows when `count <= 1` (or when scrollSnapList length === 1).

## Notable strengths

- `src/lib/blog.ts:117-150` — `extractHeadings` uses the same `slugify` rule as the MDX h3 renderer, with explicit duplicate-suffix handling. The contract between the loader and the renderer is documented in both places.
- `src/lib/blog.ts:255-287` — `getAllPosts` is wrapped in `React.cache`, fails loudly on duplicate slugs / unknown authors / unknown scholarship slugs, drops drafts in production, and sorts newest-first. Great single-source-of-truth shape.
- `src/lib/blog.ts:304-342` — `getRelatedPosts` ranking is well-considered: tiered (series → tag overlap → category → recency) with a numeric tagOverlap tiebreaker. Algorithm is O(n) per call, fine for the post count.
- `src/components/blog/callout.tsx` — Clean CVA-based variants, semantic `<aside role="note">`, icon `aria-hidden`, accessible label. Good template for other tonal components.
- `src/components/blog/blog-detail.tsx:114-191` — Sticky sidebar with progressive disclosure (md horizontal strip, lg full sidebar) is a nice editorial touch. The `top-32` aligns with the `scroll-mt-32` on h3 anchors so click-to-scroll lands cleanly under the sticky header.
- `src/components/blog/blog-grid.tsx` — Correctly resets `page` to `null` when filter changes (avoids stale empty pages), and clamps `safePage` so out-of-range URLs don't crash.
- `src/app/blog/[slug]/page.tsx:22` — `export const dynamicParams = false` correctly forces only known slugs to render, returning 404 for everything else without server work.
- `src/app/blog/[slug]/page.tsx:24-27,42` — `toAbsoluteUrl` for OG images is the right move; relative OG URLs break when shared.
- `src/hooks/use-has-mounted.ts` — Elegant `useSyncExternalStore` implementation that avoids the `useState`+`useEffect` hydration anti-pattern. The JSDoc explains the intent clearly.
- `src/hooks/use-media-query.ts` — Same pattern, returns `null` for unknown server-side state so consumers can gate render until the answer is real (used at `blog-filters.tsx:61-63`).
- `src/components/blog/blog-detail-skeleton.tsx` — Reasonable structural fidelity with the real layout (sidebar shape, content rhythm, related posts row). Better parity than the grid skeleton.
- `src/components/contact/contact-faq.tsx` — Properly uses `aria-expanded`, `aria-controls`, and `role="region"` + `aria-labelledby`. Most accordion implementations get one of these wrong.
