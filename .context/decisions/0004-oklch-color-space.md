# ADR 0004 — OKLCH for all color tokens

**Status:** Accepted
**Date:** 2026-03

## Context

The Academic Curator aesthetic relies on a small palette of warm, slightly desaturated colors (brownish-red, sage, terracotta, cream). We needed a color space that:

- Renders predictably across light and dark themes.
- Supports tonal scales (lowest → highest container surfaces) without muddy mid-tones.
- Plays nicely with TailwindCSS v4 (which natively supports modern color spaces).

## Decision

All design tokens are defined in **OKLCH** in `src/app/globals.css`, exposed as CSS custom properties.

## Why

- Perceptually uniform: doubling lightness in OKLCH produces a visually doubled lightness, unlike sRGB/HSL.
- Tonal layering (`--container-lowest` … `--container-highest`) can be generated by walking `L` while keeping `C` and `H` constant.
- Tailwind v4 supports `oklch()` natively in arbitrary values — no preprocessor needed.
- Future-proof: P3 / wide-gamut displays render OKLCH correctly without extra tooling.

## Consequences

- AI suggestions that hard-code hex colors must be rejected — reference tokens instead.
- Anyone editing the palette must edit `globals.css`, not individual components.
- Color-mixing logic (hover states, focus rings) uses `color-mix(in oklch, …)` rather than RGB blends.
